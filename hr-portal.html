HR Portal

A multi-tenant SaaS HR management system built with Flask + SQLAlchemy on the backend and vanilla JS on the frontend. Each organisation is fully isolated via org_id. Access is governed by role-based permissions down to the module level, with optional individual and department overrides.

Getting Started

Install dependencies

cd backend
py -m pip install flask==3.0.3 flask-cors==4.0.1 flask-jwt-extended==4.6.0 \
   flask-sqlalchemy==3.1.1 python-dotenv==1.0.1 bcrypt==4.1.2

Note: psycopg2-binary is only needed for PostgreSQL. Skip it for local SQLite testing.

Seed the database

py seeding.py

Creates all tables via db.create_all(), drops and recreates them on each run, then inserts 20 employees, 7 departments, 5 roles, 11 modules, and 4 demo users into hr_portal.db (SQLite).

Run the server

py app.py

Serves the API at http://localhost:5000/api/… and the frontend SPA at http://localhost:5000.

Environment Variables

Copy .env.example to .env and fill in your values. Without a .env, the app defaults to SQLite.

DATABASE_URL=postgresql://postgres:YOUR_PASSWORD@localhost:5432/hr_portal
# Default (no .env): sqlite:///hr_portal.db

JWT_SECRET=change-me-to-a-random-32-char-string
JWT_ACCESS_EXPIRES_MINUTES=60
JWT_REFRESH_EXPIRES_DAYS=7
FLASK_DEBUG=false
PORT=5000

Auth API  /api/auth

MethodPathAuthDescription
POST/login—Returns access_token, refresh_token, user, permissions{}
POST/refreshRefresh tokenIssues a new access token
GET/meBearerCurrent user + role info

The permissions map from login drives the frontend sidebar — only modules with can_view: true appear.

JWT claims carry org_id, role_id, role_code, email, full_name, employee_id, department_id — so middleware never needs extra DB lookups for basic identity.

Permission resolution order

Department override (highest) → Employee override → Role default (baseline)
Department permissions win if set. If not, individual employee override wins. If neither, falls back to the role's permission.

RBAC & Multi-tenancy

Multi-tenancy

Every tenant-scoped table has an org_id UUID column with a FK to organizations. All service queries hard-filter by org_id extracted from the JWT — no cross-tenant data leakage is possible at the ORM layer.

Role-based access control

The @require_permission(MODULE_CODE, action) decorator on every route checks the resolved permission before the handler runs. Actions are view · create · edit · delete.

@bp.get("/")
@require_auth
@require_permission("EMPLOYEES", "view")
def list_employees(): ...
